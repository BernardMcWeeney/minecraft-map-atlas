# Realm Map Editor v2 (uNmINeD / OpenLayers)

This is a local-browser / static-hostable add-on to uNmINeD's **Web page** export. It does **not** contain the terrain tiles; those are generated by uNmINeD from your own Minecraft Bedrock world.

## What's new in v2

- **Click any existing marker or boundary** with **Browse / Details** to open its profile.
- Edit **name, ruler/owner, description and colour** without deleting or redrawing it.
- **Hide a single item's label** by unticking "Show this name on the map". Boundary remains visible/clickable.
- **Hide all labels** with one toggle (available to ordinary visitors too).
- Visitors who click a marker, path or kingdom see a **read-only profile** with its description and approximate X/Z centre.
- **Move / Edit Shape** still changes polygon and line geometry, independently of names/profile.
- Supports existing **v1 `annotations.json`** and existing **v1 browser drafts** (the localStorage key is preserved).

## Upgrading a map that's already working (like your screenshot)

1. On the current local editor at `http://localhost:8000/?edit=1`, click **Export JSON**. **Keep that backup**; your current work may exist only in browser storage.
2. Stop the local Python server with Ctrl+C.
3. In your existing uNmINeD **web export folder**, replace **only** `realm-map-editor.js` with this v2 file.
4. **Do not overwrite your existing `annotations.json` with the blank file from this ZIP**. Replace `annotations.json` only with your own downloaded backup from step 1 if you want that to become the public/visitor version.
5. Start your server again: `py -m http.server 8000`.
6. Hard-refresh the browser (Ctrl+Shift+R) and open `http://localhost:8000/?edit=1`.
7. Choose **Browse / Details** and click a coloured territory. Edit its Name, Owner, Description, Colour and Show Label checkbox.
8. When done, click **Export JSON**. Replace `annotations.json` with the downloaded file. Test `http://localhost:8000/` **without** `?edit=1` to confirm what visitors will see.

`?edit=1` is a local editing UI toggle only. It is **not authentication** and it does **not save to Cloudflare automatically**. Anyone can append `?edit=1` to a public Pages URL, but their changes remain only in their own browser until somebody with deployment access publishes a replacement `annotations.json`.

## Fresh installation (new uNmINeD Web page export)

1. Export your Minecraft world using uNmINeD's **Web page** export (not Image).
2. Copy `realm-map-editor.js`, `patch-unmined.py`, and the sample `annotations.json` into the generated folder next to `index.html`.
3. In Command Prompt, opened in the export folder, run:

   ```cmd
   py patch-unmined.py
   py -m http.server 8000
   ```

4. Visit `http://localhost:8000/?edit=1` to edit and `http://localhost:8000/` to browse the published annotations file.
5. Back up your data frequently with **Export JSON**. It creates a portable `annotations.json` in Minecraft X/Z coordinates.

The `patch-unmined.py` script is safe to run again; it detects when the map has already been patched.

## Cloudflare Pages (no public server needed)

**A. Check the number of files in your uNmINeD export.** Open PowerShell inside the export folder:

```powershell
(Get-ChildItem -Recurse -File | Measure-Object).Count
```

At the time of writing, Cloudflare Pages Free supports **20,000 files per site**, and **25 MiB maximum per individual asset**. Dashboard drag-and-drop allows up to **1,000 files per deployment**. Larger maps under 20,000 files should be deployed with Wrangler. Check Cloudflare's current limits before uploading: https://developers.cloudflare.com/pages/platform/limits/

**B. Publish** (small map, at most 1,000 files):

1. Open Cloudflare dashboard > **Workers & Pages** > Create > **Pages** / **Direct Upload**.
2. Drag the **whole uNmINeD web export folder** (containing `index.html`, JS, `annotations.json`, and tile folders) into the uploader.
3. Deploy. You'll receive a `*.pages.dev` URL; you can also attach a custom domain.

**C. Publish** (larger map, up to 20,000 files): requires Node.js on the computer running the deployment; in a terminal in the export folder:

```powershell
npx wrangler login
npx wrangler pages project create realm-map
npx wrangler pages deploy . --project-name realm-map
```

When you change profiles and export a new `annotations.json`, **replace the one in the folder and redeploy**. Because Pages is static, browser-local edits cannot overwrite the deployed file.

If the exported map has **more than 20,000 files**, Pages Free will not host all those tiles as-is. Reduce the uNmINeD export area/zoom levels or host the tile assets separately (for example R2, which may incur charges), or self-host them on your own server. Don't assume a giant map will fit the free tier.

**Privacy:** Published Pages URLs are public by default. They can reveal the coordinates of player bases and kingdoms. Use Cloudflare Access (or another supported access control) if you want the site private; hiding a link or adding `?edit=1` is not security.

## Edit workflow

- **Browse / Details:** click territory/marker/path to rename, set owner, type description, recolour, toggle that name.
- **Marker:** click to place, give name.
- **Boundary:** click polygon corners, double-click to finish, give name.
- **Road / Path:** click line vertices, double-click to finish.
- **Move / Edit Shape:** drag vertices to modify geometry (does not erase metadata).
- **Delete:** click feature and confirm.
- **Hide all labels:** affects only how labels appear in that particular browser; it does not remove profile names or annotations.
- **Export JSON:** saves all annotation data to your downloads (includes descriptions, owners, colours and per-item label visibility).
- **Import JSON:** loads any existing annotation file and replaces your draft after confirmation.
- **Reset draft:** removes the editor's browser copy and reloads the deployed `annotations.json`.

No external JS libraries or Python packages are required beyond the OpenLayers already included by uNmINeD. Python's built-in `http.server` is needed only while working locally. Cloudflare serves the static files directly.

## Known limitations

- Tested for JS syntax, Python patch execution, data migration and annotation serialization; **not tested against your exact exported uNmINeD files**. The existing working v1 script integration is unchanged.
- `?edit=1` does not create an administrator login, shared drafts, or online autosaving. For real shared, authenticated edits, add an API using Cloudflare Workers plus storage (e.g. D1/R2) and access controls.
- Coordinates displayed on territory profiles are the **approximate centre of their bounding box**, not necessarily the geometric centroid.
- Descriptions are displayed as plain text, not raw HTML (safer for publicly hosted maps).
